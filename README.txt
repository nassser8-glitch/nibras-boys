نظام المدرسة — نسخة الخادم متعدد المستخدمين
=============================================

هذا المجلد هو الخادم الكامل للرفع على أي استضافة تشغّل Node.js + PostgreSQL.
الواجهة موجودة في public/index.html (نفس نسخة index.html الجذرية تماماً؛
نسخة demo/ مبنية منها عبر سكربت build_demo.js).

بنية التقنية
  Node.js (Express 5) + PostgreSQL 17 (حزمة pg) + bcryptjs لتشفير كلمات المرور.
  جلسات مذكّرة على الخادم (كوكيز HttpOnly + SameSite=Strict)، مدتها 24 ساعة.

محتويات المجلد
  server.js          الخادم (Express + pg)
  db.js              طبقة قاعدة البيانات
  migrate.js         ترحيل بيانات server/data/*.json إلى PostgreSQL
  public/index.html  الواجهة المصدرية (طبقة المصادقة والمزامنة عبر الخادم)
  public-build/      نسخة الرفع المغلفة (obfuscated) — استخدمها في الإنتاج
  build_obfuscate.js سكربت بناء public-build من public/index.html
  data/              بيانات الترحيل الأصلية (لا تُنقل أي بيانات قديمة)
  package.json       التبعيات وأمر البدء

التغليف (حماية كود المتصفح)
  الواجهة كود جانب متصفح (HTML/JS) — يُسلم لكل زائر، فلا يمكن منع نسخه
  نهائياً، لكن نسخة الرفع مبنيّة عبر javascript-obfuscator لجعل قراءته صعبة:
    node build_obfuscate.js   ← يُنتج public-build/index.html (نفس مجلد public)
  للرفع في الإنتاج شغّل الخادم بـ:  WEBROOT=public-build node server.js
  المصدر readable يبقى في public/index.html، وكل مخرجات العروض الأخرى
  (الجذرية وdemo وعدم الاتصال) تُبنى من المصدر. أُنفّذ npm audit: 0 ثغرات.

علامة الملكية
  كود التطبيق موثّق باسم مالكه ناصر العتيبي (nassser8@gmail.com) في ثلاثة
  مواضع: (1) تعليق حقوق أعلى المصدر، (2) سطر «جميع الحقوق محفوظة» أسفل شاشة
  الدخول وأسفل الإطار العام، (3) صفحة «حول التطبيق» من القائمة الجانبية

التشغيل محلياً
  1. جهّز قاعدة PostgreSQL فارغة مخصصة لهذا الخادم (لا تشاركها مع أي تطبيق آخر).
  2. اضبط DATABASE_URL على اتصال تلك القاعدة الفارغة.
  3. البدء:  npm start   (يخدم على http://localhost:8090)
     عند أول تشغيل: يُنشئ الخادم الجداول تلقائياً (initSchema) ثم يُنشئ حساب
     المدير admin@nibras.local بكلمة مرور مؤقتة عشوائية تُطبع على الشاشة مرة
     واحدة فقط — احفظها فوراً (ستُفرَض على المدير تغييرها عند أول دخول).

مهم — قاعدة الإنتاج المخصصة (nibras_prod)
  قاعدة neondb الحالية على Neon مبنية لمخطط Prisma/Next.js ولا تعمل مع هذا
  الخادم (جدول users فيها بلا أعمدة school/data وبنية كلمة مرور مختلفة).
  تم إنشاء قاعدة منفصلة في نفس مشروع Neon باسم nibras_prod لهذا الخادم،
  وقاعدة nibras_test استُخدمت للاختبار وحُذفت.
  لاستخدامها: خذ قيمة DATABASE_URL من ملف .env واستبدل  /neondb?  بـ  /nibras_prod?
  مثال:  ...?sslmode=require  يبقى كما هو، فقط يتغير اسم القاعدة في المسار.
  عند أول تشغيل عليها سيُطبع المدير المؤقت على الشاشة (القاعدة حالياً فارغة
  وجاهزة). يُفضَّل استخدام sslmode=verify-full بدل prefer/require.

متغيرات البيئة
  PORT             رقم المنفذ (افتراضي 8090)
  DATABASE_URL     معرّف الاتصال بـ PostgreSQL
                   (افتراضي: postgres://postgres:Nibras@Postgres_2026@127.0.0.1:5432/nibras)
  SESSION_TTL_MS   عمر الجلسة بالمللي ثانية (افتراضي 86400000 = يوم)
  MAX_BODY_MB      الحد الأقصى لحجم الطلب MB (افتراضي 20)
  TRUST_PROXY      اضبطه =1 عند التشغيل خلف وكيل عكسي (لقراءة IP الحقيقي)
  FORCE_HTTPS      اضبطه =1 لتحويل كل الطلبات إلى HTTPS (خلف وكيل يدعمها)
  WEBROOT          مجلد الصفحات (افتراضي: public بجانب server.js)

الحسابات الافتراضية
  لا توجد أي حسابات بكلمات مرور ثابتة أو معروفة. عند أول تشغيل يُنشأ حساب
  المدير admin@nibras.local بكلمة مرور مؤقتة عشوائية تُطبع على شاشة الخادم
  مرة واحدة فقط، ويُجبَر على تغييرها عند أول دخول. بقية المستخدمين يُنشئهم
  المدير عبر إدارة المستخدمين (توليد كلمة مرور مؤقتة تُعرض مرة واحدة).

سياسة أول تسجيل دخول
  أي مستخدم جديد (يُنشأ عبر إدارة المستخدمين) يدخل أول مرة فيُجبَر على
  تعيين كلمة مرور خاصة (≥ 8 محارف) قبل السماح له بتعديل أي بيانات.

الصلاحيات (يُفحص قسم القسم المتغير في PUT)
  ADMIN   كل شيء.
  AGENT   إدارة المستخدمين + كل أقسام البيانات.
  COUNSELOR  الصفوف والفصول والطلاب (الدرجات، الشعب، الحضور، الملاحظات،
             النقل، الأنشطة، الجدول).
  TEACHER الحضور، الملاحظات، النقل، الأنشطة، الجدول (لا يدير مستخدمين).

واجهة برمجية رئيسية
  GET  /api/auth/accounts           قائمة الحسابات للعرض (بريد + دور فقط، بلا كلمات مرور)
  POST /api/auth/login              تسجيل الدخول (بريد + كلمة مرور)
  POST /api/auth/logout             تسجيل الخروج (تتطلب مصادقة)
  GET  /api/auth/me                 جلسة المستخدم الحالية
  POST /api/auth/change-password    تغيير كلمة المرور
  POST /api/auth/update-profile     تحديث البريد / كلمة المرور
  POST /api/auth/admin/create-user      إنشاء مستخدم (توليد كلمة مرور مؤقتة تُعرض مرة واحدة)
  POST /api/auth/admin/reset-password   إعادة تعيين (توليد كلمة مرور مؤقتة تُعرض مرة واحدة)
  GET  /api/db/:school              جلب بيانات القسم
  PUT  /api/db/:school              حفظ بيانات القسم (بضبط صلاحيات)
  GET  /api/health                  فحص الصحة

الاستضافة والـ HTTPS
  شغّل خلف وكيل عكسي (Nginx/Caddy) ينهي TLS ثم وجّه الطلبات إلى المنفذ
  الداخلي، واضبط TRUST_PROXY=1 و FORCE_HTTPS=1 لتحويل كل شيء إلى HTTPS.

أمان ملاحظات
  - لا يوجد SYNC_KEY ولا EmailJS ولا أي كلمة مرور في كود المتصفح — المصادقة
    جلسات خادم فقط، وقائمة الحسابات تُعرض بلا كلمات مرور.
  - كلمات المرور تُشفر bcrypt ولا تُخزَّن نصاً، ولا تُطبع على الشاشة إلا مرة
    واحدة (كلمة مؤقتة عند أول تشغيل أو عند إعادة تعيين).
  - أي مستخدم جديد يُجبَر على تعيين كلمة مرور خاصة عند أول دخول قبل التعديل.
  - قيد معدل الطلبات على الدخول والإنشاء وإعادة التعيين وتغيير كلمة المرور.
  - مزامنة المتصفحات عبر الخادم تلقائياً؛ آخر تعديل هو الحاكم.
